# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

A collection of shell scripts that scaffold new projects with opinionated defaults. Not a runnable application — the scripts generate applications.

- `new-next.sh` — scaffolds a Next.js project (App Router, TypeScript, Tailwind, shadcn/ui, Kysely + graphile-migrate, Better Auth, Vercel AI SDK, Jotai)
- `new-nest.sh` — scaffolds a NestJS project (TypeScript, Prisma, Better Auth, `@thallesp/nestjs-better-auth`)

## Tech Stack of Generated Projects

Both scripts produce projects using **pnpm**, **PostgreSQL**, and **Better Auth** with admin/apiKey/anonymous plugins. The database layer differs by script:

- **Next.js stack**: App Router (no Pages Router, no src dir), Turbopack, shadcn/ui (all components), Jotai, Vercel AI SDK, `@better-fetch/fetch`. Database: **Kysely** (query builder, `pg` driver) with types generated by **kysely-codegen**, and **graphile-migrate** for SQL migrations. Better Auth connects via a raw `pg.Pool`.
- **NestJS stack**: `@nestjs/config` (global), `@thallesp/nestjs-better-auth`, body parser disabled in `main.ts`, default port 3001. Database: **Prisma** via `@prisma/adapter-pg` with client output in `../src/prisma/generated`.

## Testing Changes to Scripts

There are no automated tests. To verify a script change:

```bash
# Next.js script (placeholder DB types let the build pass before codegen)
./new-next.sh test-app && cd test-app && pnpm build

# NestJS script
./new-nest.sh test-app && cd test-app && pnpm prisma generate && pnpm build
```

Clean up test output with `rm -rf test-app`.

Note: the Next.js script cannot run `kysely-codegen` at scaffold time because it
introspects a live database. The generated `lib/db-types.ts` ships a placeholder
`DB` type so `pnpm build` succeeds; real types come from `pnpm db:codegen` after
migrations are applied against a running Postgres.

## Key Patterns in the Scripts

- Docker Compose config is generated into `docker/compose.dev.yml` (Next.js only) with Postgres, Redis, and Mailpit
- `BETTER_AUTH_SECRET` is auto-generated via `openssl rand -base64 32` with a fallback string
- **Next.js** uses Kysely (`lib/db.ts`, a dev-global singleton) with codegen'd types in `lib/db-types.ts`; migrations are managed by graphile-migrate via a `.gmrc.js` that `require('dotenv/config')` (graphile-migrate does not auto-load `.env`). DB connection strings (`DATABASE_URL`, `SHADOW_DATABASE_URL`, `ROOT_DATABASE_URL`) come from env. `npm pkg set` adds `db:*` and `auth:generate` scripts.
- **NestJS** uses Prisma with a custom output path (`../src/prisma/generated`, added to `.gitignore`) and `env("DATABASE_URL")` directly in `schema.prisma`
- Better Auth schema is generated via `pnpm dlx @better-auth/cli@latest generate --yes`. For Next.js, `--output migrations/current.sql` writes the SQL straight into graphile-migrate's current migration; for NestJS it generates the Prisma schema

## When Editing Scripts

- The scripts use heredocs (`cat > file <<EOL ... EOL`) to generate files. Watch for shell variable expansion — `$` characters intended for the generated code must be escaped as `\$`.
- Generated file paths differ between Next.js (root-level `lib/`, `auth.ts`) and NestJS (`src/` directory structure).
- After modifying dependencies, keep the README.md feature lists in sync.
